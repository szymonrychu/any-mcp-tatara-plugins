# any-mcp-tatara-plugins memory

Lessons that outlive a session. Newest first.

- 2026-11-02 (fix/history-search-cursor): `history_search` now answers `{next_before_id, sessions}` with the cursor FIRST and a default `limit` of 20 (max stays 200; the plugin fills the default, any-mcp does not apply schema defaults). Why: any-mcp `shape_default` keeps the head of an over-budget text (`DEFAULT_BUDGET_CHARS` 40000) and drops the structured value, and a 50-hit page is ~60k chars, so the cursor emitted last was cut with the tail and the superleader could not page. `test_history_search_cursor_survives_the_output_budget` pins it through the real harness pipeline.
- 2026-11-02 (session-history P1): `history_search`, `history_get` and `history_records` are GET rows in `admin.py` after the chats; there is no `history_delete` and `test_history_has_no_delete` pins it (user decision Q2.6: deleting a stored session is for the user in the web UI). The relay filters a history page after paging and sends the upstream cursor in `X-Next-Before-Id` (also on an empty page, ruling S-R1); only the header carries it, so `OrchestratorPlugin.call` wraps the `history_search` list as `{sessions, next_before_id}` (int or null) and leaves `history_get` and `history_records` unchanged (the relay sends no cursor there). Plain `list` answers cannot carry a field, hence the object. The OpenAPI fixture got the three history routes from agents-orchestrator session-history 78923eac (see `.source`); the rest is kept from hive-self-close because that branch predates `/agent/v1/close`, so re-vendor the fixture whole once the orchestrator session-history branch has merged main. No version bump here: the release commit takes the next free minor.

- 2026-11-02 (hive-self-close P1, v0.10.0): `self_close` is a declarative `spec` row (`POST /agent/v1/close`, body `{reason}`, reason 1..500) after `chat_status`; its description is the contract for agent behaviour (last action of the turn, leader only, about 30 s after idle, user can cancel), so edit it only together with the orchestrator close rules. The OpenAPI fixture was refreshed from agents-orchestrator branch hive-self-close 2736bda; the only diff is `/agent/v1/close`. Version is 0.10.0, not 0.7.0: tatara-2 already released 0.9.0 (controller ruling H-R7). The version lives in `orchestration/orchestrator/pyproject.toml`, `uv.lock` and `tests/test_source_install.py`.

- 2026-11-02 (agents-taskboard Task 11, v0.9.0): the ten task tools live in `tasks.py` (`task_tools`), declarative like the admin rows, relayed under `/agent/v1/tasks...` plus `PUT /agent/v1/session/labels`. Methods: task_update and todo_update are PATCH, todo_set PUT, decision_withdraw POST `.../decisions/{id}/withdraw`. Label params accept any string up to 40 chars (max 20 items) with the pattern `^[a-z0-9-_.:]{1,40}$` only in the description, not as a schema `pattern`: the server normalises (trim, lowercase) first, so a strict pattern would refuse input the server accepts. `outputSchema` requires `url` only on the single-task tools; list and labels results carry it as an optional property because their upstream shapes differ. The OpenAPI-pin test in `test_admin_tools.py` is limited to the admin rows: its fixture is an extract that predates the relay routes. The version lives in `orchestration/orchestrator/pyproject.toml` (and `uv.lock`, `test_source_install.py`).

- 2026-11-01 (superleader-crud PL2 fix round 1): `to_file` is confined to `secrets_dir` (default `~/.agent-secrets`, created 0700, real paths compared so symlinks and `..` fail), refuses an existing file unless `overwrite: true`, never follows a symlink target. `preset_create`, `preset_replace` and `session_create` refuse a protected env entry with a `value` (error names the variable, points to `secret_set`) before any request: the open `spec` schema would otherwise carry it into the transcript.

- 2026-11-01 (superleader-crud PL2): `secret_set` is registered by `load_tools` and `SecretResolveError` is routed in `on_error` (text `<tool> failed: <class>`). `to_file` is not a separate local tool: the four webhook tools that can receive an issued credential stay declarative rows and `OrchestratorPlugin.call` wraps them (pops `to_file`, validates it before any request, sends `X-Orch-Tool: local` only when it is given, drops `credential` from every answer, writes it with `write_credential`: 0600 temp file in the target directory then `os.replace`). Why: reuses the binding, path filling and upstream error mapping instead of a second HTTP path. The tool is named `secret_set` as in L1 (the plan text says `preset_secret_set`). Protected-only is enforced by the orchestrator (422 for a name that is not a protected variable); the plugin does not duplicate that check.

- 2026-11-01 (superleader-crud PL1): the admin tools are rows in `admin.py` (`AdminRow`), not hand-written `spec()` calls, so one table feeds `load_tools` and the contract test. The test pins method and path (parameter names normalised) of every http tool to `tests/fixtures/orchestrator_openapi.json`, a /agent/v1-only extract of the orchestrator's `openapi.json` (superleader-admin 461a85d); refresh it when the orchestrator API changes. Relay routes have no request schema upstream, so row schemas come from the upstream services' committed OpenAPI documents and are closed (`additionalProperties: false`). No row takes a `password`: webhook credentials are issued by the upstream and stored by the orchestrator. Chat admin tools are named `chat_admin_*`/`chat_rule_*` to avoid the user-chat tools `chat_rooms`/`chat_send`.

- 2026-10-31: non-declarative (local) tools in any-mcp: a `ToolSpec` with `handler=async (ToolCall) -> value` instead of `http=`; the `Plugin.call` hook runs the handler, so the arguments stay in-process. `orchestration/orchestrator/.../secrets_local.py` builds `secret_set` this way (`local_secret_tool`); `Plugin.on_error` hides exception text, so the plugin's `on_error` must route `SecretResolveError` to `secret_error_result` (PL2 wires both into `load_tools`). Errors carry fixed class names only, never value, path or command output.
